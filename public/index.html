Every byte on this page came off a raw TCP socket.

No Express, no http module. This page is served by a hand-written HTTP/1.1 parser, and every control below talks to it live — watch the wire panel on the right fill in as you go.

GET / + POST /echo

The root route serves this page through the same cache-aware file handler used for every static file below. /echo reads the request body back byte for byte — nothing is parsed or transformed.

GET /sheep

Ten chunks, 500 ms apart, streamed with Transfer-Encoding: chunked from an async generator on the server. No buffering, no Content-Length known up front.

GET /files/hello.html — conditional caching

Fetch the file once and capture its Last-Modified timestamp. Fetch it again with that timestamp as If-Modified-Since, and the server sends back a 304 with an empty body instead of the file.

GET /files/test.txt — byte ranges

test.txt is 17 bytes: Test file content. Pick a slice and the server returns just those bytes as 206 Partial Content, with a matching Content-Range header.

A malformed or inverted range isn't rejected with 416 here — it silently falls back to a full 200 response. Known gap, not hidden.

WS / — WebSocket echo

The handshake is a hand-rolled SHA-1 + magic-string exchange. Every text (and binary) frame you send comes back as a text frame prefixed Echo: — there's no binary echo path.

not connected

A silent heartbeat keeps the connection alive in the background — nothing to watch here, it just doesn't drop.

Path safety & 404s

Every file path is resolved against public/ with path.normalize("/" + uriPath) before being checked — that collapses any ../ segments, so a traversal attempt lands inside the public directory instead of escaping it, and simply 404s.

How it's built

Every HTTP request runs this pipeline, in order:

Parser→ Router→ Cache / Range→ Gzip→ Writer

A WebSocket upgrade is detected straight off the parsed headers and hands the socket to the frame loop before the router ever sees it — the two pipelines only share the parser.
